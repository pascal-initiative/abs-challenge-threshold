# Sprint 1 methodology

## Sources and snapshot

MLB Stats API schedule (`/api/v1/schedule`) and completed game feeds (`/api/v1.1/game/{game_pk}/feed/live`) establish game inclusion and the physical-pitch universe. Baseball Savant daily [Statcast CSV](https://baseballsavant.mlb.com/statcast_search) supplies pre-pitch state, participants, location, movement, and release information. The official [ABS team-detail service](https://baseballsavant.mlb.com/leaderboard/services/abs/139?year=2026&challengeType=team-summary&gameType=regular&level=mlb&id=139&groupBy=) supplies historical challenges for each of 30 teams. Endpoint and schema discovery used the official leaderboard client. No third-party research dataset or model is used.

The [Savant dashboard](https://baseballsavant.mlb.com/abs) daily `absSummaryData` independently supplies the expected challenge counts. Its `vizChallenges` array covers only the latest week and is unsuitable as the pilot challenge population. Its descriptive page also specifies that ABS challenges are prohibited when a position player pitches.

All downloads have SHA-256 content-addressed raw objects and append-only receipts. Transformations verify hashes and run offline. Derived artifacts use stable row order and deterministic JSON/CSV serialization; no timestamps enter processed tables. Acquisition timestamps remain in receipts. Cached URLs do not refresh. Preserve objects for exact historical reproduction; a new root is required for a fresh source snapshot. Failures remain in the receipt history; the most recent receipt for a URL determines its current acquisition status.

## Inclusion and pitch extraction

The pilot uses MLB (`sportId=1`), regular season (`gameType=R`), official game dates August 24–30, 2026 inclusive, and final status. `officialDate` is the game-assignment date, not the UTC date of each pitch. All 93 eligible games were downloaded and processed. This rule includes the full game assigned to a pilot date; it does not filter individual pitch timestamps. Suspended/resumed games would retain this assignment policy and need separate investigation if the intended research population changed.

Every feed event with `isPitch=true` produces a row. The deterministic key is `game_pk:at_bat_index:play_event_index`. Nonpitch events remain in raw feeds. Called codes are `B`, `*B`, `C`, `P`, and `I`; swinging strikes, fouls, contact, hit-by-pitches, and automatic penalties do not enter the called-pitch population. The feed's `isStrike` alone is never a called-strike indicator. All noncalled physical pitches remain in the final table with `UNKNOWN / NOT_CALLED_PITCH` and are excluded from called-pitch summary denominators.

## Joining Statcast and participants

Join within game and zero-based plate appearance (`at_bat_number - 1`). Sort Statcast records by its pitch number after separating `automatic_ball` and `automatic_strike`; sort feed physical pitches by event order. Require equal complete physical-pitch sequence lengths and singleton source rows, then pair physical ordinals. Preserve both pitch-number conventions. Semantic checks compare common call descriptions, including contact; any conflict or unmatched physical Statcast row blocks release. The pilot has 117 automatic records, preserved in the audit, and 37 physical pitches with differing source numbers. These are documented conventions, not unexplained source disagreements.

Batter, pitcher, and catcher IDs come from the matched pre-pitch Statcast record. Names come from the feed's player map. Feed matchup IDs are a labeled-by-source fallback for batter/pitcher on unmatched rows, never for catcher; release blocks if a called pitch lacks a catcher. This avoids treating a final boxscore catcher as the catcher for earlier pitches. The home-plate official comes from the feed's boxscore `officials`; multiple or missing home-plate assignments produce null and block release. A midgame umpire replacement not represented there remains a source limitation.

Balls, strikes, outs, runner IDs, and scores all come from pre-pitch Statcast fields. `score_diff` is home minus away. No post-plate-appearance scores, runners, or final game outcomes are used. A blank matched runner ID means an empty base; a missing Statcast match means unavailable state. Automatic count changes are already represented in the next physical pitch's pre-pitch state. The table labels all these values `PRE_PITCH`.

## Official challenges and original calls

Savant team-detail responses include overlapping for/against copies. Group records by `(game_pk, play_id)`, normalize the official fields, and require copies to agree. Keep the source object digest, original record indices, and copy count. Conflicting copies are preserved and block release; they are not silently resolved. Unknown challenger identities or outcomes remain unknown. Determine BATTER/CATCHER/PITCHER only by exact challenger-ID equality with the participants.

`original_isStrike_ump` explicitly establishes the original call. `is_challengeABS_overturned` indicates whether to invert it to recover the official decision. Thus official call reconstruction uses outcome bookkeeping, independently of the geometry calculation. Both calls remain separate from the feed's displayed, potentially post-review call. Challenge pitch matching uses the official play UUID and game ID. The pilot has 188 batter, 247 catcher, and 12 pitcher challenges. All 447 match, and the seven daily totals reconcile (52, 91, 68, 26, 79, 72, 59).

Feed review type `MJ` is a cross-check, not the challenge population. Every such review must reconcile to Savant; where review details exist, check outcome agreement. The displayed feed call must agree with the official post-review call. These discrepancies block release. No assumption that generic `hasReview` enumerates all ABS challenges is used.

## Geometry fixed before validation

The [MLB adoption rules](https://img.mlbstatic.com/opprops-images/image/upload/opprops/jgdgj1bak2bgiskwpdnm.pdf) define a 17-inch rectangle at mid-plate, with lower and upper limits at 27% and 53.5% of certified batter height. Any ball overlap counts as a strike. Teams start with two challenges, keep successful ones, and receive one on entering an extra inning only if empty. Only the batter, catcher, or pitcher may request review immediately, without outside assistance.

The [Statcast field documentation](https://baseballsavant.mlb.com/csv-docs) explicitly changes `plate_x`/`plate_z` to mid-plate and `sz_top`/`sz_bot` to ABS bounds beginning in 2026. The pipeline uses this version-specific definition rather than assuming historical operator zones apply. Original CSV zone bounds and feed zone values are preserved; `abs_zone_top`/`abs_zone_bot` are separately labeled copies under this documented 2026 interpretation. Roster-listed heights are not substituted for certified measurements. Statcast movement and release values retain their source units; feed movement stays in separate inch-valued fields.

The official [Savant zone visualization code](https://builds.mlbstatic.com/baseballsavant.mlb.com/v1/sections/homepage-new/builds/e03823d6301cce7f3555537b367f719eccb28333/scripts/build/chunks/zone-Cpwqk-Fc.js) declares a ball radius of `2.9 / 2 / 12` feet. This public visualization value is the fixed reconstruction assumption, not a claim to have MLB's internal adjudication code. It was selected before comparing pilot outcomes. The algorithm computes signed Euclidean distance from ball center to the rectangle and subtracts the radius; distance <= 0 is STRIKE. This correctly treats corners as rounded ball/rectangle intersections, unlike expanding a rectangle into a larger square-cornered box. Distance is in feet, negative inside the strike region, positive outside. Missing/invalid geometry or non-2026 records produce unknown. No parameter search, outcome-dependent adjustment, or record removal is used.

## Inventory and legal availability

Replay each game's physical pitches in plate-appearance/event order. Record both teams' counts *before* processing that pitch's challenge. Confirmed challenges consume one; overturned challenges retain it. At the start of each extra inning, replenish an empty inventory to one exactly once per full inning; do not replenish at the half-inning change. Inventory follows the team when offense/defense changes. Unknown outcomes propagate unknown inventory for that team; incomplete challenge coverage makes inventory unknown throughout the run. Negative inventory or a challenge by the wrong affected team blocks release.

For an original strike, the affected team is offense; for an original ball, defense. Positive inventory implies availability only when the pitcher is eligible. Feed `primaryPosition` P/TWP is treated as pitcher/two-way; other positions indicate position-player pitching and legal unavailability. Missing position produces unknown availability. This designation is a documented public-data proxy; a future roster designation ambiguity requires investigation. The pilot has 107 pitches thrown by players listed at non-pitcher positions, and no contradictory official challenges. This is not an inference from pitch speed or score.

## Validation and classification

Compare derived against official calls for **every** challenge. Report matched/unmatched, comparable/uncomparable, agrees/disagrees, and breakdowns by original call and outcome. The primary agreement denominator includes all official challenges; a comparable-only rate is also supplied. Release requires a nonempty fully reconciled population, full matching and comparisons, >=99% agreement, complete game coverage, required catcher/umpire IDs, unique pitch keys, and no material join, source, or inventory discrepancies. Every nonagreement is written to `validation_discrepancies.csv`, including missing comparisons. Small disagreements are never dropped even if aggregate agreement passes.

The pilot passes: **447/447, 100%**. There are 249 overturned and 198 confirmed outcomes and zero geometry discrepancies. Zero disagreements do not establish perfect accuracy for the unchallenged population; challenged pitches are a selected validation sample and published measurements have finite precision.

After the gate passes: agreeing original/derived calls are CORRECT_CALL; incorrect calls officially overturned to the derived call are CORRECTED; incorrect calls with legal availability and no successful challenge are SURVIVED_RECOGNITION (distinguish NOT_CHALLENGED and CHALLENGED_BUT_CONFIRMED); incorrect calls with exhausted inventory are SURVIVED_RESOURCE. Missing, conflicting, or otherwise unsupported cases are UNKNOWN. An official/derived conflict on an apparently correct call stays UNKNOWN. A confirmed challenge contradicting the derived call is explicitly preserved, not collapsed. None occur in this pilot.

Position-player pitching is a separate legal restriction, not exhaustion. The allowed class vocabulary has no dedicated class for it, so 12 incorrect calls remain UNKNOWN with reason POSITION_PLAYER_PITCHING. No physical rows are deleted.

## Metrics and exploratory summaries

Let E be called pitches with original and derived calls and no source conflict; I is the subset with differing calls. C, R, and U count CORRECTED, SURVIVED_RECOGNITION, and SURVIVED_RESOURCE. Rates are: incorrect_call_rate = I/E; correction_rate = C/I; survival_rate = (R+U)/I; recognition_survival_rate = R/I; resource_constrained_survival_rate = U/I. Zero denominators yield null. Known incorrect calls with UNKNOWN class stay in I and are reported separately, so correction plus classified-survival rates need not sum to one. The 12 legally unavailable cases explain the pilot residual.

Every count/rate is reported overall and separately for offensive (original strike) and defensive (original ball) populations. The total-pitches count within each split is restricted to that population. Breakdowns for the requested dimensions include recognition-survivor count, called-pitch denominator, incorrect-call denominator, and available-incorrect-call denominator, with a clearly named rate for each. Identity groups are sorted by identifiers, never by performance. Distributions use available SURVIVED_RECOGNITION observations: n, missingness, min/max, mean, sample standard deviation, and linear-interpolated quartiles. No causal interpretation, significance test, ranking, or predictive model is produced.

## Limitations and stop policy

Public endpoints and schemas can change; feeds and Statcast may be revised after retrieval. Statcast precision and the assumed ball radius can matter at boundaries. Current boxscore umpire assignment and roster primary position have the limitations above. The automatic-event sequence rule is validated with source fixtures and semantic checks, but future unusual scoring events must not be silently matched. Unknown runner state must not be interpreted as an empty base when the source match is missing. Per-team overlapping challenge copies are audited, while dashboard daily counts provide independent coverage accounting within the same authoritative service.

The requested stop conditions are enforced before downstream release. Investigate any unavailable authoritative source, unexplained mismatch, unreliable participant identification, rule ambiguity, insufficient geometry agreement, or material disagreement. Preserve interim evidence; do not tune for interesting results or lower the gate. Raw source responses can contain Savant's unrelated modeled metrics; those are neither used nor copied into the research dataset. See the generated pilot and data-quality reports for exact results.
